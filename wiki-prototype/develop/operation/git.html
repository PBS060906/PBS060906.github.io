Git

Git 是分布式版本控制系统。理解其三层区域（工作区 → 暂存区 → 版本库）后，一切命令都能推出来。

核心概念

工作区 git add → 暂存区 git commit → 版本库 git push → 远程仓库

日常命令速查

场景命令
克隆仓库git clone <url>
查看状态git status / git diff
暂存与提交git add -p → git commit -m "msg"
拉取更新git pull --rebase
推送git push origin main
撤销工作区修改git restore <file>
回退提交git reset --soft HEAD~1
查看历史git log --oneline --graph

分支操作

git switch -c feature/demo   # 创建并切换
git merge feature/demo       # 合并（保留分叉历史）
git rebase main              # 变基（线性历史）
git branch -d feature/demo   # 删除分支

Question

团队约定优先：共享分支用 merge 保平安，个人分支合入主干前 rebase 求整洁。绝不 rebase 已推送的公共分支。

后悔药速查表

改错了别慌，先判断改动走到哪一层，再对症下药：

场景解法
改了，没 addgit restore <file> 丢弃工作区修改
add 了，没 commitgit restore --staged <file> 移出暂存区，改动仍在工作区
commit 了，没 pushgit reset 回退，三种模式见下表
push 了git revert <commit> 生成反向提交，不改写历史，公共分支可用
彻底找不回git reflog 兜底，见下文

reset 三种模式

模式工作区暂存区适用场景
--soft保留保留只撤销 commit，改动原样保留，可重新提交
--mixed（默认）保留清空撤销 commit 和 add，重新挑选要暂存的内容
--hard清空清空彻底丢弃，未提交改动一并消失，慎用

最后一张底牌是 git reflog：它记录 HEAD 的每一次移动，找到出事前的哈希值后 git reset --hard <hash> 即可回去——只要 commit 过，基本都能救回。只想把某个已有提交“复制”到当前分支，则用 git cherry-pick <hash>。

stash 临时存档

改动写到一半需要切分支，又不想提交半成品，先存档再走：

git stash        # 存档全部未提交改动，工作区恢复干净
git stash list   # 查看存档列表（stash@{0} 为最新）
git stash pop    # 恢复最近一次存档，并删除该记录

远程协作

git fetch 只下载远程更新、不动本地分支（先看再合）；git pull 相当于 fetch + merge，一步到位。遇到冲突按三步走：

git status 定位冲突文件 → 手动修改，删除 <<<<<<< 等标记 → git add 后 git commit 收尾

rebase 后需要强推时，用 --force-with-lease 代替 --force：后者无条件覆盖远程历史，若同事在此期间推送了新提交会被直接抹掉；前者多一层校验——仅当远程还停在你本地已知的提交上才允许覆盖，否则拒绝推送，避免误删他人的工作。

大文件与 .gitignore

# .gitignore 示例
node_modules/    # 依赖目录，绝不入库
dist/            # 构建产物
*.log            # 所有日志文件
.env             # 密钥与私密配置
!keep.log        # ! 取反：该文件是例外，需要跟踪

大文件已经提交过怎么办：先补一条 .gitignore 规则，再执行 git rm --cached <file> 让仓库停止跟踪（本地文件保留）并提交；若要从历史中彻底清除，需要用 git filter-repo 之类工具重写历史。

实用别名

高频命令配个短别名，少敲很多字：

git config --global alias.st status          # git st
git config --global alias.sw switch          # git sw
git config --global alias.lg "log --oneline --graph"
git config --global alias.undo "reset --soft HEAD~1"

提交信息规范

<type>(<scope>): <subject>

feat(auth): 支持手机号验证码登录
fix(api): 修复分页参数越界
docs: 补充部署说明
