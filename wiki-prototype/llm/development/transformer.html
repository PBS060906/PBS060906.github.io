Transformer

Transformer 以自注意力取代循环结构，实现完全并行的序列建模，是大模型的标准架构。

整体结构

整体为「Token Embedding + 位置编码 → Transformer Block × N → 最终层归一化 → LM Head → 下一 Token 概率」；每个 Block 内部依次为多头自注意力、残差连接 + RMSNorm、FFN / SwiGLU、残差连接 + RMSNorm。

Token Embedding→ 多头自注意力→ 残差连接 + RMSNorm→ FFN / SwiGLU→ 残差连接 + RMSNorm × N 层→ LM Head

自注意力机制

Attention(Q, K, V) = softmax(QK⊤ / √dk) V
  • Q、K、V 由输入线性变换得到；
  • √dk 缩放防止点积过大导致 softmax 饱和；
  • 多头机制让不同子空间各自关注不同模式。

最小实现

import torch, torch.nn.functional as F

def attention(q, k, v, mask=None):
    d_k = q.size(-1)
    scores = q @ k.transpose(-2, -1) / d_k ** 0.5
    if mask is not None:
        scores = scores.masked_fill(mask, float("-inf"))
    return F.softmax(scores, dim=-1) @ v

多头注意力的形状注释

多头最易出错的是形状变换：拆头与合并各对应一次 view + transpose，全程盯着四维形状即可。

def multi_head_attention(x, n_heads, Wq, Wk, Wv, Wo, mask=None):
    # x: [batch, seq, dim]，Wq/Wk/Wv/Wo: [dim, dim]
    B, S, D = x.shape
    d_head = D // n_heads
    q = x @ Wq  # [batch, seq, dim]
    k = x @ Wk  # [batch, seq, dim]
    v = x @ Wv  # [batch, seq, dim]
    # 拆头：把 dim 维切成 n_heads 份，头部维提到第 1 维
    q = q.view(B, S, n_heads, d_head).transpose(1, 2)  # [batch, heads, seq, dim]
    k = k.view(B, S, n_heads, d_head).transpose(1, 2)  # [batch, heads, seq, dim]
    v = v.view(B, S, n_heads, d_head).transpose(1, 2)  # [batch, heads, seq, dim]
    out = attention(q, k, v, mask)                     # [batch, heads, seq, dim]
    out = out.transpose(1, 2).reshape(B, S, D)         # 合并多头: [batch, seq, dim]
    return out @ Wo

三种架构谱系

同样的注意力模块，按掩码方式与堆叠结构组成三种谱系，分别对应不同的任务形态：

架构代表模型注意力掩码适用任务
encoder-onlyBERT、RoBERTa双向（全序列可见）文本分类、信息抽取、句向量
decoder-onlyGPT、Llama、Qwen、DeepSeek因果掩码（只看过去）对话、代码、推理等生成任务
encoder-decoderT5、BART编码双向 + 解码因果 + 交叉注意力翻译、摘要等序列到序列转换

如今生成模型主流是 decoder-only，原因有三：其一，它与 next-token prediction 训练目标天然统一，不存在"预训练目标与使用方式脱节"的问题；其二，只有一种注意力、结构最简单，规模化与工程实现成本最低；其三，因果注意力正是 KV Cache、批处理等推理优化的前提，整个推理生态都围绕它建设。实践反复验证：数据与规模足够时，decoder-only 在理解类任务上同样不落下风。

KV Cache

自回归生成时，历史 token 的 K、V 不再变化。把每层每头的 K/V 缓存下来，每步只需计算新 token 的 Q 和新 K/V，避免对整段前缀重复做注意力——这就是 KV Cache，Decode 阶段能快起来的根本原因。

KV ≈ 2 × 层数 × nheads × dhead × seq_len × dtype 字节
  • 因子 2 对应 K 与 V 两份缓存，显存随上下文长度与并发数线性增长；
  • 长上下文 + 高并发时 KV Cache 会反超权重，成为显存第一大头；
  • 下表"注意力"一行的 GQA / MLA，本质就是减少 KV 头数来压缩这项开销。

动手算一笔账：7B 模型（32 层、32 头、head_dim=128）fp16 下每 token 的 KV Cache = 2 × 32 × 32 × 128 × 2 字节 = 512 KB，一条 4096 token 的序列约 2 GB，16 路并发仅 KV Cache 就要 32 GB——这正是 模型推理与服务 一节讨论 PagedAttention 与量化的动机。

训练目标

目标极简：对语料每个位置做 next-token prediction，用交叉熵最大化真实下一个 token 的似然：

L(θ) = −∑t log Pθ(xt | x<t)

causal mask 在训练中同时解决两件事：保证位置 t 只能看到过去（与推理时的信息可见性一致），又让整段序列一次前向时所有位置的损失并行计算。由此形成鲜明对比：训练并行、推理串行——训练时掩码代替了逐个生成，推理时必须一个 token 接一个 token，KV Cache 才应运而生。

Scaling Law

损失随参数量、数据量、算力按幂律平滑下降。Chinchilla（2022）给出关键修正：给定算力预算，参数量与训练数据量应同比扩张——此前多数模型"参数偏大、数据偏少"，并未训到最优。由此确立了"小模型 + 充分数据"的路线：7B 级模型在数万亿 token 上训练后，性价比远超同算力训练的更大模型，也解释了开源小模型为何能逼近早期大模型。

预训练与后训练

一个能对话的模型不是一次训出来的，而是流水线的产物：

预训练→ SFT 指令微调→ RLHF / DPO 偏好对齐→ 对齐后模型
  • 预训练：海量语料上的 next-token prediction，注入语言与世界知识，占总算力 95% 以上；
  • SFT：数万到百万条高质量指令数据微调，让模型学会"听指令、按格式回答"；
  • RLHF / DPO：用人类偏好信号做对齐，压低有害输出、提升回答质量；
  • 对齐后模型：发布上线，进入 模型推理与服务 环节。
